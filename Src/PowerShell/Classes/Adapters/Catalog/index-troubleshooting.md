# Adapter troubleshooting: JSON v2 and targeted parts

This is the single authoring and retrieval guide for [index-troubleshooting.json](./index-troubleshooting.json) and its canonical constructor, invoke and named concrete part shards. These files are source-backed documentation for a relevant observed error. They do not implement a reader, change the ordinary [catalog](./index.json), load themselves into normal plan context, execute a correction, or authorize a provider retry. Current owner inspections include unresolved and partial coverage; Data covers SQL/ADX only and excludes ArtifactProcess implementation and error entries. A missing route means no diagnosis from this catalog.

## Find one entry after an observed error

Use the retrieval contract below. The adapter identity must come from verified dispatch/context, the activity from the observed call when available, and the emitted message from a known structured field or documented wrapper. Search [the troubleshooting manifest](./index-troubleshooting.json) outside prompt context, select one route, then resolve its owner and part, read exactly one part shard, and include only the selected entry and cited provenance. For a vague label such as `Prompt Not Found`, request the exact emitted message and source context; the label does not select the Foundry empty-prompt route. If the message, owner, source hash or selector is unknown, stop with the specified no-selection outcome.

## JSON v2 contract

All files are UTF-8 JSON objects; field names and identifiers are case-sensitive. Required means present and non-null. Strings described as text are nonempty, non-whitespace strings; arrays preserve author order. Unknown object members are rejected in v2 author validation (except free text values); missing optional fields mean absent, not null. Numbers below are integers. Consumers reject an unsupported `version`, including v1-only readers of v2; optional-field extensions require a new documented version and affected compatibility review. No changes to Catalog version/layoutVersion or existing consumers.

**Manifest `Catalog/index-troubleshooting.json`**

| Field | Type/cardinality and rule |
| --- | --- |
| `version` | required integer, exactly 2 |
| `catalogManifest` | required string, exactly `index.json`; resolves beside the troubleshooting manifest within the same Catalog root |
| `owners` | required array, one row per reachable mapped/container/condenser owner; no duplicated activities or properties |
| `owners[].ownerId` | required string; `Mapped/<name>` or `Condensers/<name>`, unique ordinal case-sensitive and case-insensitive to prevent filesystem collisions |
| `owners[].mappedAdapter` | required string; root manifest name; for condensers exactly MappedCondenserAdapter |
| `owners[].condenser` | optional string; required only for Condensers owner, exact nested name; prohibited for Mapped owner |
| `owners[].status` | required enum: `documented`, `no-verified-errors`, `unresolved` |
| `owners[].inspection` | required text, concise inspected source boundary and reason for status; no claim that absence of documented errors proves infallibility |
| `owners[].parts` | required array of unique `{part,file}` rows, one for each nonempty canonical target; `part` is `constructor`, `invoke`, or a declared concrete adapter name. Zero verified entries means `[]`; no filler shard. |
| `owners[].sourceInventory` | required full ordered array of the original owner source records, including uncited inspection records and `matrixRef`; `[]` for owners with no source shard |
| `owners[].unverified` | optional array 1..N of unchanged candidate objects with required `id`, `reportedText`, `reason`, `neededEvidence` texts; IDs do not collide with verified entries; no route or correction |
| `routes` | required array, 0..N; only entries whose status is source-verified appear |
| `routes[].ownerId`, `routes[].entryId` | required strings; pair unique, resolves to the corresponding shard entry |
| `routes[].part` | required exact owner part key; `(ownerId, part, entryId)` resolves one verified entry in one canonical part |
| `routes[].adapters` | required array 1..N of distinct adapter identifiers satisfying the owner-kind rule below; no wildcards |
| `routes[].activities` | required array 1..N of distinct declared activity names, or single reserved token `@construct` for source-verified construction errors; never mix @construct with activities |
| `routes[].messages` | required array 0..N of distinct exact thrown/logged constant messages; no aliases/patterns; byte-for-byte equal to the shard's emittedMessages[].text projection |
| `routes[].aliases` | optional array 1..N distinct search labels; identical to shard aliases; cannot authorize a match by themselves |
| `routes[].patterns` | optional array 1..N pattern objects, identical to shard patterns defined below; never executable regex/code |

**Part shard `Catalog/{Mapped,Condensers}/<owner>-troubleshooting-<part>.json`**

| Field | Type/cardinality and rule |
| --- | --- |
| `version`, `ownerId`, `mappedAdapter`, `condenser` | same types/values as manifest row; version exactly 2 |
| `part` | required exact owner part key matching manifest `owners[].parts` and canonical file |
| `sources` | required ordered subset of owner `sourceInventory`, containing exactly records cited by this part’s entries; full object equality required |
| `sources[].id` | required unique text identifier |
| `sources[].repository` | required text; exact known repository name from catalog/matrix, resolved through trusted local repository mapping, never an arbitrary remote URL |
| `sources[].path` | required repository-relative path to existing source, forward slashes; containment rules below |
| `sources[].sha256` | required 64 uppercase hexadecimal chars, mechanically captured from current source bytes, never substituted for historical matrix identities |
| `sources[].symbol` | required nonempty function/class name or `file` when no symbol applies |
| `entries` | required array 1..N of verified entries assigned to this one part; no duplicate owner entry IDs across parts |
| `entries[].id` | required lowercase stable kebab-case text (`^[a-z][a-z0-9-]*$`), unique in shard; composite ownerId/id is global identity |
| `entries[].status` | required string exactly `source-verified`; runtime validation must not be implied |
| `entries[].adapters`, `entries[].activities` | same as routes; selectors obey the owner-kind rule below; ordinary activities must exist in that owner's catalog |
| `entries[].emittedMessages` | required array 0..N objects: required `kind` enum `throw` or `log`, `text` exact constant string, `evidence` evidence-reference array 1..N; assembled wrapper text allowed only with evidence for both wrapper and inner constant |
| `entries[].aliases` | optional array 1..N distinct search labels; explicitly non-emitted, supported by a reason in `aliasRationale` (required text if aliases present) |
| `entries[].patterns` | optional array 1..N objects: required `kind` exactly `prefix-suffix`, `prefix` text, `suffix` string (empty allowed), `evidence` 1..N refs. Both bounds case-sensitive, anchored; minimum input length sum of bound lengths; no capture storage or regex. Only documented variable messages may use them. At least one nonempty bound; broad wrappers shared by different errors cannot alone identify an entry. |
| `entries[].trigger` | required object: `condition` text and `evidence` 1..N refs describing actual guard/branch and prerequisites |
| `entries[].likelyCauses` | required array 1..N objects: `text`, `basis` enum `source` or `hypothesis`, `evidence` 1..N refs for source, prohibited for hypothesis; hypotheses explicitly require discrimination before correction |
| `entries[].diagnostics` | required ordered array 1..N step objects defined below; read-only/local, no secrets/body dumps or provider action |
| `entries[].correction` | required object: `boundary` text, `steps` 1..N step objects, `stopWhen` 1..N text strings; proposed user/operator action only, not automatic authority |
| `entries[].verification` | required ordered array 1..N step objects; state observable expected condition and whether static or separately authorized runtime; no success guarantee from documentation |
| `entries[].redaction` | required text naming relevant excluded sensitive values and safe retained metadata |
| `entries[].limitations` | required 1..N texts, including source-only confidence and uncertain/unknown branches |

Evidence-reference objects have exactly `sourceId` (required text resolving this part’s sources.id and its owner sourceInventory), `startLine` and `endLine` (required integers, 1 <= startLine <= endLine within current file). Optional `matrixRef` object on a source has required `file` (fixed project-relative historical matrix shard), `sourceId` (text) and `note` (text on retained historical/current distinction); absent when there is no useful join. Do not fabricate matrix IDs. Line ranges aid inspection; hash binds the cited bytes. Steps have required `action` and `expected` texts, required `mode` enum `static-read`, `local-edit`, `separately-authorized-runtime`, optional `evidence` array 1..N refs; diagnostics allow only static-read; correction allows static-read/local-edit; verification allows static-read or separately-authorized-runtime. Source-based factual claims must have evidence in the step or the entry's trigger/cause references; speculative actions must explicitly say conditional/unverified and cannot prescribe correction without a verified discriminator.

Owner-kind selector rule (manifest and shard): for `Mapped/<name>`, each adapter selector must equal a concreteAdapters[].name declared by that mapped catalog, or the mapped owner's own name with direct source evidence of a mapped-level error. For `Condensers/<name>`, each adapter selector must equal that concrete condenser catalog's `name`, verified through the nested MappedCondenserAdapter reference; no concreteAdapters array is required on a condenser catalog. Activities are checked against that same owning catalog. Thus owner Condensers/FormatCondenser with adapter FormatCondenser and activity Json is valid; adapter PlanCondenser under that owner is invalid. Runtime aliases require verified resolution to this canonical identity before lookup, not arbitrary acceptance as selectors.

Every verified entry and its route must have at least one exact emitted message OR at least one source-evidenced bounded pattern; reject both empty/absent. Required messages/emittedMessages arrays may be empty for a variable-only error. The exact-message projection and pattern equality between route and shard remain mandatory. For example, FormatCondenser logs `Failed to resolve content at path: $DefaultPath` at current source lines 53, 73, 93 and 118: its source-backed pattern may have prefix `Failed to resolve content at path: ` and suffix `""` (the empty JSON string), with no invented constant path or exact message. This is a specification/validation example, not an additional required pilot shard. Never retain or inject the variable path value; diagnostics use redacted metadata. Check exact-versus-pattern and pattern-versus-pattern overlap for intersecting adapter/activity selectors; ambiguous candidates return no selection, and detected ambiguous authoring must be resolved before acceptance. Pattern-only entries retain all provenance, guard, bounded-correction and privacy requirements.
Manifest/part status consistency: documented means at least one verified entry and no unresolved candidates; unresolved means unresolved candidates or an incomplete source boundary, whether verified entries exist or not; no-verified-errors means completed bounded source inspection found no supported entries/candidates and no part needed. An unresolved owner lacking a part must explain unavailable source/evidence in inspection. The campaign cannot be presented as full coverage accepted while unresolved owners remain. Root template and empty container owners are inspected/accounted without invented error entries. Generic error fallback entries are prohibited.

Safe reference rules: owner and concrete part names come only from the live ordinary catalog and match `^[A-Za-z][A-Za-z0-9_]*$`. Canonical part paths are `Mapped/<owner>-troubleshooting-<part>.json` or `Condensers/<owner>-troubleshooting-<part>.json`; condenser direct activity errors use `invoke`, not a redundant condenser-named part. Reject traversal, rooted/drive/URI paths, encoded separators, symlink/reparse escape, case-insensitive collisions, unsuffixed ordinary catalogs and arbitrary manifest-supplied paths. `catalogManifest` resolves only `index.json`; every owner part resolves only its exact suffixed canonical path. The ordinary catalog and its readers remain troubleshooting-free. Source paths remain in their trusted repository and matrixRef within its existing matrix directory. Reject duplicate route keys, entry IDs, source IDs, cross-part overlapping exact messages/patterns with intersecting selectors and unsupported versions.

### Retrieval contract (future reader; no implementation in this campaign)

1. Normal task/planning context loads no troubleshooting JSON or prose, including colocated index-troubleshooting.json and index-troubleshooting.md. Only a relevant observed error activates lookup. Use adapter identity, activity when available, and extracted error message; never use model guesses as adapter identity. Map runtime adapter identity to exact catalog identity using verified dispatch metadata. Missing/ambiguous adapter identity returns `needs-context`, with no part loaded.
2. A lightweight retrieval operation searches manifest routes outside the prompt. Prefer case-sensitive whole-message equality, then anchored prefix-suffix matches. Do not silently strip text, case-fold or assume arbitrary logger wrappers. Only extract an inner message from a known structured error field or explicitly documented wrapper; otherwise return unmatched. Aliases are search labels only. An alias-only report never selects or loads a part; require verified canonical adapter/activity context and an exact emitted message or anchored documented pattern. A vague label such as Prompt Not Found does not auto-load the Foundry empty-prompt entry.
3. Filter by exact adapter and, if supplied, activity. Missing activity is acceptable only if all matching routes identify one owner and one entry; otherwise ask for activity. Zero candidates -> `unknown-error`, no part. Multiple remaining entries/owners -> `ambiguous`, no part; request discriminating adapter/activity/message context. Never fall back to loading all owners. Keep error text transient; do not log full request/response/credentials.
4. Resolve the single route's owner row and safe path, validate version/cross-references and provenance freshness against available source. A stale/unknown source identity -> `stale-evidence`, no correction recommendation; request current source review. Resolve `ownerId` plus `part` through the owner row, validate its canonical path and read exactly ONE part shard. Include only its selected entry and cited provenance in the future error-specific prompt/context; other entries in that file are not injected. Errors arising later start another independent targeted lookup. Do not prefetch sibling parts, v1 owner shards or all owners.
5. Output selected owner/entry, matched exact message or documented pattern, source-only confidence, bounded diagnostics/correction/verification and limitations. An alias-only report remains unselected until exact/pattern and canonical context are verified. Do not execute steps from the document. Provider retry is never implicit.

## Maintain an affected owner

1. Read the live ordinary [manifest](./index.json) and its exact owner catalog; for a condenser, reconcile the nested [MappedCondenserAdapter](./Mapped/MappedCondenserAdapter.json) names and order. A new concrete under an existing mapped owner belongs in that mapped owner's named concrete part. An inline template or activity-empty owner receives a truthful inspection, not a fabricated route.
2. Inspect current direct source, dispatch and helper guards for the affected owner. Update the owner's inspection status and constructor, invoke or concrete part only where source proves the emitted message, selector, trigger and useful bounded diagnostics. Assign each verified entry once by the emitter and guard in its trigger/emitted-message evidence, never by @construct or the selector alone. The mapped owner's own Start/factory/registration guard goes to constructor; mapped dispatch/Invoke/forwarding and directly owned helper guards go to invoke. Concrete and direct-helper emissions, including concrete @construct errors, go to that named concrete part. A mapped wrapper that cites the leaf guard stays with the leaf; a distinct mapped wrapper guard belongs to invoke. A shared helper with an evidenced single owner and several selectors stays once in that owner's invoke part; uncertain cross-owner attribution stays unverified and unrouted pending evidence. Condenser construction/registration guards go to constructor; declared activity and directly owned helper failures go to invoke. Only a separately declared concrete identity gets a named condenser part; never create a redundant condenser-self concrete part. Keep unverified reports on the owner row and unrouted; preserve full ordered sourceInventory, including uncited records.
3. When membership or a message/guard/correction changes, update the exact route projection and source hashes with the affected entry. Keep the human part links above in manifest order and synchronized with nonempty `owners[].parts`; owners with zero verified entries have no file link. Remove only an unreferenced part under an authorized change; preserve prior review history. For result or dispatch changes, follow the ordinary result-contract/catalog/matrix duties and revisit troubleshooting only when ownership, selector, emitted meaning or recipe changes.
4. Validate affected JSON v2 fields, canonical paths, live owner closure, current source identities, exact/pattern projection and collision behavior. Check wrong context, unknown and stale evidence. Preserve normal-context exclusion: ordinary JSON manifests and readers do not reference troubleshooting parts, and Markdown discovery links do not request recursive loading. Static documentation checks do not prove runtime/provider success.

Corrections in entries are conditional proposals for a human/operator with verified ownership and effect state. Keep secrets, message variable segments, payloads, paths, response bodies and provider diagnostics transient and redacted as the entry requires. Stop when source attribution or safe state is unavailable.
