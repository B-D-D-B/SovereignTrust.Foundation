## Selection contract

| Condition | Required behavior / discriminating check |
| --- | --- |
| Variable absent | Legacy relative-path selection remains the explicit fallback for an untouched caller. Record selected canonical path/hash and matched dependency. In the parity launcher, require explicit reviewed selection; do not silently fall back. |
| Variable present but blank, relative, malformed, nonexistent, wrong module or identity mismatch | Fail before module initialization/provider effects. Treat blank as invalid, not absent; record whether the environment provider/platform can distinguish empty from absent. If it cannot, the launcher records an explicit selection-state input and rejects ambiguous state rather than promising that distinction. |
| Selected manifest valid | Canonical absolute manifest path, expected hash, module identity and all selected dependency identities match the reviewed selection packet. Read/validate under SP-01 safeguards; a fresh hash does not adopt an unapproved input. Reject redirection/replacement/drift while preparing child inputs. |
| Foundation already loaded | Enumerate exact loaded module Path/ModuleBase/identity including duplicate versions/nested copies, plus loaded SignalGraph/type/assembly provenance. Accept only the one selected snapshot/dependency set. Any mismatch or unknown type origin requires a fresh process; no Remove-Module/Import-Module -Force hot switching. Name/version equality alone is insufficient. |
| Worker/runspace/child | Pass explicit selection packet and process environment before parsing/import; validate again inside each worker before runtime initialization. Do not assume inherited machine settings or parent import forces a worker hardcoded relative path to match. |
| Same inputs, different selected snapshots | Separate fresh PS processes select A and B; each root and worker reports its own selected identities with no cross-load. Invalid/loaded-mismatch cases must fail before any fixture operation. |
