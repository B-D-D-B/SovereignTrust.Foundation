## Minimal proposed change

1. **Allow optional Content at the wrapper.** Read actual Config.Content without logging a terminal missing/null error before source selection. Preserve distinction between null/missing and nonnull values; avoid pipeline enumeration/coercion that loses false, zero, empty strings or empty byte arrays. Pass the actual value to the existing helper. Unexpected resolution/type errors remain errors, not silent fallback.
2. **Choose exactly one source mode.** If Content is nonnull, use Content, even when false, 0, `''` or empty byte[]. Do not resolve, stat, open or check permissions of SourcePath in this branch; an invalid/unreadable supplied path cannot defeat valid Content. Only when Content is null/missing, resolve the optional SourcePath with existing token/path semantics and local-file rules. A blank/missing path, nonexistent file, directory, inaccessible file or unusable provider path returns a clear failed operation without dispatching a write. Preserve existing typo compatibility for SourthPath only as already supported; do not add a new alias contract.
3. **Prepare one cloned transport request.** Preserve caller-plan identity/state and unrelated authentication/header/content-type settings. Remove inactive source fields from the clone, not from the caller. Content mode: remove Config.SourcePath/SourthPath and stale alternative transport fields; assign Config.Body by presence, including an empty string/zero-length byte array. File mode: set Config.SourcePath to the resolved actual local leaf path; remove stale Config.Body/Content/JsonBody/Form rather than accidentally choosing a previous body. Content mode likewise cannot fall through to stale Form/JsonBody. Keep existing JSON object/array and scalar conversion conventions, user ContentType override and default MIME choices; byte[] remains exact binary and is never JSON/text-converted. Do not re-enable commented ReadAllBytes merely because it exists: use the established InFile path for file uploads, retaining exact bytes including zero-length files.
4. **Repair only the necessary existing REST seam.** Its current truthy nonstring Body conversion JSON-serializes byte arrays; exclude byte[] and use nonnull/body-presence handling for empty bodies and content headers. Its InFile invocation currently does not assign `$response`; capture the existing REST response and preserve applicable existing status/error/auth behavior so the helper receives the normal result contract. Keep Body and InFile mutually exclusive and never convert a file to text. Do not redesign retry, transport, auth or response schemas. Subsequent file-access or transport errors remain failures. InFile reads the file at transport time; an intervening readable content change is not guaranteed detected, and no validation-to-upload snapshot guarantee is claimed.
5. **Retain failure provenance and return semantics.** Use canonical current SignalGraph logging/status APIs and actual ErrorRecord.Exception; preserve the same operation Signal and native identity, existing parent relationships, failure propagation and execution-context diagnostics. Do not swallow failures, continue the test after a failed operation, or repair unrelated provider bugs.
